# 第04章 Cloudflare DNS 实战

> 这一章的标题里虽然写着「实战」，但它不是教你在某个控制台点哪里。
> 我们要建立的，是一层**认知**：为什么今天那么多网站，第一步就把 DNS 交给了一家叫 Cloudflare 的公司？它在互联网的「入口」到底站在什么位置？
> 读完后，你不一定会操作它，但你一定能在脑子里画出：当用户访问一个网站时，Cloudflare 站在哪、做什么。

---

## 一、本章目标

学习完成后，你将能够理解：

1. DNS 为什么需要专业的管理平台
2. Cloudflare 在整个互联网中的位置
3. 域名解析是如何经过 Cloudflare 的
4. DNS 记录到底是什么
5. Cloudflare 为什么可以隐藏服务器地址
6. Cloudflare 如何把「域名、服务器、安全能力」连接在一起

## 二、为什么需要理解 Cloudflare

先还原一个普通用户的视角。

你眼里，上网是这样：

```
输入网址
  ↓
打开网站
```

但在第 03 章我们知道，真实过程其实更长：

```
用户
  ↓
DNS 查询
  ↓
找到服务器
  ↓
建立连接
  ↓
获取内容
```

如今互联网越来越复杂。一个网站光有「地址」和「服务器」已经不够了，它还想要：

- **加速**：让全球用户都打开得快
- **安全**：挡住恶意攻击
- **稳定**：大流量下也不崩
- **防攻击**：不被恶意流量挤爆

于是，原本单纯的「查地址」，逐渐演成了一个更复杂的角色。

**Cloudflare 不是简单的 DNS 工具，它更像一座城市的「入口管理中心」。**

对比一下访问方式的变化：

```
普通访问：
用户
  |
 DNS
  |
服务器

现代访问：
用户
  |
Cloudflare
  |
服务器
```

差别就在这中间多出来的那一层。

---

## 三、从 DNS 到 Cloudflare：互联网地址系统升级

承接第 03 章：传统 DNS 只回答一个问题——

> 「这个名字对应哪个地址？」

```
example.com
  ↓
IP 地址
```

但现代互联网对「地址系统」提出了更高要求：

- **更快寻找**：全球访问都要快
- **全球访问**：访客可能来自任何国家
- **防护攻击**：挡住恶意流量
- **隐藏源站**：不让外人直接摸到服务器

于是，DNS 逐渐从一个「查地址的电话簿」，升级成了**互联网的入口**。

```
DNS 发展过程：

普通 DNS
  ↓
智能 DNS
  ↓
Cloudflare 等全球入口平台
```

Cloudflare 站在的位置，正是这个升级后的「入口」。

## 四、Cloudflare 是什么

这一节是重点。先划清它**不是**什么：

- **不是服务器**（不存放你的网站内容）
- **不是网站**（它自己不提供具体业务）
- **不是 VPN**（它不改变你的网络路径去绕过限制）

它的位置，在**用户和服务器之间**。

用统一比喻来说：

- **服务器** = 真正经营店铺的人，房子里有真东西
- **Cloudflare** = 这座城市的「入口物业管理中心」

物业负责什么？

- **指路**：告诉访客怎么找到店铺（DNS）
- **分流**：把人多的时候引导到不同入口（CDN）
- **检查**：看看来的人是不是坏人（安全）
- **防护**：挡住恶意冲击（DDoS）
- **加速**：让东西送得更快（缓存）

```
访问者
  ↓
物业管理中心（Cloudflare）
  ↓
商店（服务器）
```

记住一句话：**服务器是房子的主人，Cloudflare 是房子门口的管理中心。**

## 五、域名接入 Cloudflare 后的变化（重点）

这是理解 Cloudflare 最关键的一张图。先对比「有没有它」。

### 没有 Cloudflare 时

```
用户
  ↓
DNS
  ↓
服务器 IP
  ↓
服务器
```

用户查询后，直接拿到服务器的真实地址。

### 接入 Cloudflare 后

```
用户
  ↓
DNS
  ↓
Cloudflare
  ↓
源服务器
```

关键变化是：**用户首先找到的是 Cloudflare，而不是直接找到服务器。**

画成位置图更直观：

```
传统：
        网站服务器
             ↑
             |
用户 -------- 网络

现代：
用户
  ↓
Cloudflare 入口
  ↓
服务器
```

Cloudflare 成了「第一道门」。所有访客先进这道门，再由它决定怎么走到后面的服务器。

## 六、什么是 DNS 记录

前面几章提过，这里系统地说一遍。

**DNS 记录，就是「城市地址登记表」。**

就像城市管理中心要记录：哪个名字，对应哪栋房子。域名系统也要记录：哪个名字，对应哪个 IP。

常见类型有这些（这里只讲「是什么」，不写配置方法）：

### A 记录

域名 → IPv4 地址

（最基础的「名字指向哪台机器」）

### AAAA 记录

域名 → IPv6 地址

（同上，但给新一代更长的地址用）

### CNAME

一个名字指向另一个名字

（像「分店地址」，跟着总店走）

### MX

邮件服务器的地址

（管「这个域名的邮件该送到哪」）

### TXT

验证信息

（像贴在门上的「产权证明」，用来证明域名归你管）

用一张登记表来理解：

```
域名登记表：

名称        对应地址
www       房子 A（网站服务器）
mail      邮局 B（邮件服务器）
api        服务 C（接口服务器）
```

每一行，就是一个 DNS 记录。

## 七、Cloudflare DNS 解析过程（重点）

当用户在浏览器输入 `example.com`，且域名已经接入 Cloudflare，过程是这样的：

```
用户
  ↓
DNS 查询
  ↓
Cloudflare DNS
  ↓
返回地址
  ↓
建立连接
```

逐步拆解：

1. **浏览器询问 DNS**：「example.com 的地址是多少？」
2. **找到 Cloudflare DNS**：因为域名已经在 Cloudflare 管理下，答案由它给出
3. **Cloudflare 返回目标信息**：返回的，是 Cloudflare 这一层自己的入口地址
4. **浏览器连接 Cloudflare**：访客先连到这第一道门
5. **Cloudflare 处理请求**：再由它把请求转给后面的源服务器

注意第 3、4 步：用户拿到的地址是 Cloudflare 的，不是你服务器的。这正是下一节要讲的重点。

## 八、为什么 Cloudflare 可以隐藏服务器 IP（重点）

把服务器真实 IP 想成「房子的真实门牌号」。

### 如果没有保护

```
访问者
  ↓
服务器真实地址
```

所有人拿到的，都是房子本来的门牌。谁都能直接摸到门口。

### 有 Cloudflare 之后

```
访问者
  ↓
Cloudflare 地址
  ↓
隐藏的服务器
```

Cloudflare 对外提供一个「公共入口地址」，把后面的真实服务器藏起来。

```
没有保护：
访问者 ──→ 服务器真实地址

有 Cloudflare：
访问者 ──→ Cloudflare 地址 ──→ 隐藏服务器
```

说明：**隐藏源站 IP，只是 Cloudflare 提供的第一层保护。** 外人连你服务器在哪都看不到，自然更难直接攻击它。

## 九、Cloudflare 与 CDN 的关系（铺垫）

这一节只是铺垫，第 09 章会深入讲。现在你只需要建立直觉。

Cloudflare 在全球拥有大量节点。它的作用之一，是让访客访问「离自己最近的节点」。

```
用户 A
  ↓
附近节点

用户 B
  ↓
另一个节点
  ↓
源服务器
```

比喻成仓库体系：

```
总部仓库（源服务器）
  ↓
全球分仓（Cloudflare 节点）
```

CDN 不是简单「存图片」而已，它能缓存很多静态内容：

- 图片
- CSS（网页样式）
- JS（网页脚本）
- 视频
- 其他静态内容

访客在附近的「分仓」就能取到内容，不用每次都跑回总部。这就是「更快」的来源。

## 十、Cloudflare 与安全能力（铺垫）

现代入口不只负责「指路」，还负责「安全」。

Cloudflare 能提供的防护能力包括：

- **DDoS 防护**：挡住海量恶意请求，服务器不被挤爆
- **WAF**：像一个门卫，拦住常见的网络攻击
- **SSL/TLS**：为通信加密（下一节展开）
- **访问控制**：决定谁能进、谁不能进

比喻成物业的职责：

```
物业不只告诉你地址，
还负责：
  - 门卫（拦坏人）
  - 巡逻（持续检查）
  - 风险检查（发现异常）
```

画成访问流程：

```
访问
  ↓
Cloudflare
  ↓
检查
  ↓
允许
  ↓
服务器
```

只有「检查通过」的访问，才被放进后面的服务器。

## 十一、Cloudflare 与 HTTPS 的关系

这一节连接你后面会学到的 HTTPS（第 07 章细讲）。

访问链路里，Cloudflare 通常处在中间：

```
用户
  ↓
Cloudflare
  ↓
服务器
```

关于 HTTPS 要明确两点：

1. **加密不是 Cloudflare 发明的**。HTTPS 依靠的是 TLS 这种通信协议，是整个互联网的安全标准。
2. **Cloudflare 帮助建立安全通信**。它可以在自己这一层参与 TLS 连接，让访客到 Cloudflare 这一段是加密的。

一句话区分：

- **HTTPS** 保护「通信内容」不被偷看
- **Cloudflare** 保护「互联网入口」不被攻破

两者是不同层面的保护，互为补充。

## 十二、Cloudflare 与 VPS、NAS 的关系（重点）

这一节把整门课程串起来。后面你会陆续学到 VPS、Docker、NAS，它们和 Cloudflare 不是替代关系，而是**组合关系**。

完整架构：

```
用户
  ↓
域名
  ↓
Cloudflare
  ↓
VPS 服务器
  ↓
Docker 服务
  ↓
NAS 数据
```

每一层各管一摊：

- **域名**：地址（叫什么名字）
- **Cloudflare**：入口管理（谁来、怎么进）
- **VPS**：计算空间（跑程序的机器）
- **Docker**：运行环境（把服务装进独立「房间」）
- **NAS**：数据中心（存你的照片、文件等仓库）

它们合在一起，就是一套个人数字基础设施的雏形。Cloudflare 守在最前面那道门。

## 十三、普通人为什么需要理解 Cloudflare

你可能会想：我又不开公司，干嘛懂这个？其实它和你的数字生活息息相关：

1. **建个人网站**：第一步往往就是接入 Cloudflare
2. **使用 VPS**：你买的服务器，要靠它对外暴露名字
3. **搭建 NAS 远程访问**：回家访问家里的「仓库」，要经过这道入口
4. **学习互联网架构**：理解现代网站怎么运转
5. **理解 HTTPS 和安全**：明白入口防护是怎么回事
6. **AI 时代个人基础设施**：未来你的数据和智能服务，也建立在这样一套入口之上

强调一句：**理解 Cloudflare，不是为了去当管理员，而是为了理解现代互联网到底是怎么运行的。**

## 十四、本章总结

把全章浓缩成一条知识链：

```
域名
  ↓
DNS
  ↓
Cloudflare 入口
  ↓
服务器
  ↓
服务
```

五句话记住：

1. **域名**是互联网的地址名称。
2. **DNS**负责寻找地址。
3. **Cloudflare**成为现代互联网的入口。
4. **服务器**负责提供服务。
5. **安全、速度、稳定**，是现代互联网的基础能力。
